# Agent 설계

| 단계 | 입력 | 처리·출력 |
|---|---|---|
| analyze | 요청, 직전 질문·응답·계획 | 모델이 의도, 캐릭터, 희망 구간 또는 날짜가 선택적인 마감 시각을 구조화한다. 캐릭터 선택 요청은 정해진 조회 경로로 처리한다. |
| lookup | 분석 결과, 같은 캐릭터의 조회 캐시 | characters → debut → runtime 순서로 호출한다. 첫 등장만 묻는 요청은 runtime을 생략한다. 확인 요청이나 도구 불필요 분기는 바로 답변으로 전달한다. |
| decide | 회차·러닝타임·시청 조건, SQLite의 겹치는 일정 | 가능한 시청 구간이나 마감 기준을 계산한다. 회차, 시청 시간, 제외 사유와 출처를 반환한다. |
| 응답·보관 | 판단 결과와 실행 이력 | 답변, 저장 가능한 slot, trace, sources를 반환하고 세션별 직전 요청·응답·계획·캐시를 갱신한다. |

일정은 허용 구간마다 시작에 러닝타임을 더해 종료 조건을 확인한다. 겹치는 계획이 있으면 그 종료 이후를, 시간이 부족하면 다음 허용 구간을 시도한다. 최초 시도 이후 최대 3회 재계획하고 앞에서 조회한 회차와 러닝타임을 재사용한다. 마감만 있으면 마감에서 러닝타임을 빼고 전날로 넘어가는 경우를 표시한다. 계산 결과는 시청 시작 기준이며 구체적인 일정 확정은 사용자가 별도로 저장한다.

`stage_start/end`, `decision`, `plan`, `tool_start/end`, `cache_hit`, `replan`이 실행 단계에서 발행된다. 이벤트 구독자가 SQLite에 순서대로 저장한다. 브라우저는 세션 ID와 실행 ID로 현재 요청의 이벤트를 조회한다. 저장 구독자 실패는 서비스 응답 경로에서 처리한다.
